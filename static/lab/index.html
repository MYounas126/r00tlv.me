Lab

Exploit primitives you can poke at directly, in a browser tab. No virtual machine, no gdb, nothing to install and nothing that touches your own memory.

Each one is a simulation rather than a real process, so it models the behaviour honestly and says where it simplifies. They exist because some of these ideas take four seconds to understand when you can move the bytes yourself, and considerably longer when you cannot.

Smash a stack

stack overflow

Type into a 16-byte buffer and watch the extra bytes run past the end into the saved base pointer and then the return address. Turn the stack protector on and watch the same input get caught instead.

pairs with How a CPU actually works

Walk a format string

CWE-134

Type a format string and watch printf consume the stack one specifier at a time, including the register arguments that every tutorial forgets about. Then watch %n turn a read into an arbitrary write.

pairs with Four real CVEs in a 12-line C program

Poison a tcache bin

glibc heap

Free chunks into a tcache bin, corrupt a forward pointer and make the next malloc hand you an address you chose. Includes safe-linking, which is the reason most heap tutorials written before 2020 no longer work.

modern glibc, with mitigations modelled

Probably next

  • ROP chain builder. Drag gadgets into a stack and watch RIP walk through them.
  • ASLR entropy. Reload a thousand times and see the histogram of where libc landed, on 32-bit against 64-bit.
  • Integer overflow to heap overflow. The size calculation that wraps, and the undersized allocation it produces.

A note on what these are not. None of these run real code or touch real memory. They are models, and a model is only useful if it is honest about where it stops, so each page states its own simplifications. The goal is to make a primitive obvious enough that the real thing in gdb afterwards feels familiar rather than cryptic.
