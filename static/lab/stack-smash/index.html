Smash a stack in your browser

Type into the 16-byte buffer below and watch where the extra bytes go. No VM, no gdb, nothing to install. This is the same thing gets() does to a real program.

The program

void greet(void) {
    char buf[16];
    gets(buf);           /* no bounds check, writes as far as you type */
    printf("hi %s\n", buf);
}                        /* ret pops 8 bytes off the stack into RIP */

What you are looking at

Addresses increase from left to right and from bottom to top, which is the direction a hex dump reads. The stack itself grows downward, so buf sits at a lower address than the saved RBP and the return address that were pushed before it. That single fact is the whole bug: writing forward past the end of a buffer walks straight into the bookkeeping the function needs in order to return.

When ret executes it pops 8 bytes off the stack into RIP and jumps there. It has no way of telling your bytes apart from the address call originally saved. Turn on the stack protector above and a random value is placed between the buffer and the saved RBP; the function checks it before returning, so a linear overflow is caught instead of being exploited.
